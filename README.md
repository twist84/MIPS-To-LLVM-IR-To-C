# MIPS To LLVM IR To C

PS2 Emotion Engine (R5900) static recompiler research and implementation.

The project loads a PS2 ELF, discovers guest functions, builds control-flow
graphs, decodes and lifts supported R5900 instructions into per-function LLVM
IR modules, verifies those modules, and links translated host objects behind a
guest-PC dispatcher.

## Current implementation

- ELF loading and executable-segment analysis.
- Function discovery using ELF symbols, direct calls and conservative
  control-flow-aware static JALR resolution.
- R5900 instruction decoding and lifting across integer, control flow, MMI,
  COP1, and selected COP2/VU0 operations.
- Per-function LLVM IR generation and LLVM verification.
- Native host object generation through the external llvmlite validation path.
- Native object linking, dispatcher glue and runtime helper integration.
- Regression coverage for instruction semantics, control flow, function
  discovery, COP1/MMI and VU execution, including hardware-derived COP1 vectors.
- HLE-first EE/IOP runtime, original game IRX execution, CDVD/SIF/DMA,
  controller input and guest-cycle device scheduling.
- Native VU1 microprogram compilation, validated AOT loading with fallback,
  asynchronous VU1/GS workers and native WebGPU presentation.
- Guest-clock SPU2 playback, DMA/AutoDMA, voice envelopes, Gaussian
  interpolation, modulation, noise, reverb and signed mixer gains.
- Optional 48 kHz stereo PCM output through standalone raudio from the
  pinned raylib 5.5 checkout; no host device is required for guest audio state.
- Recoverable EE translation caches, live cache-miss overlays and
  profile-driven runtime diagnostics.

For the USA SLUS_214.42 ELF, the latest full-image validation discovered
7,901 functions, emitted and verified 7,901 LLVM modules, generated 7,901
native objects, and linked them into a shared translated-code library. This is
a successful translation/link milestone, not proof that every instruction is
semantically correct or that the complete game can boot.

## Backend distinction

The production path currently emits LLVM IR. Native objects for the full-image
validation were generated by the external llvmlite tooling and then linked by
the repository's object linker. The in-tree LLVM C++ object emitter remains a
stub. A limited C++ source emitter exists for a subset of straight-line
functions; a general LLVM IR-to-C source backend is not complete.

## Current validation boundary

The USA retail SDBZ (`SLUS_214.42`) HLE-first runtime has reached
interactive training gameplay with native graphics and audible audio,
without a BIOS dependency. The 2026-11-25 10:48 replay stopped at its
configured 40-million-dispatch limit, with 16,219 cached EE IR modules,
396,717 native VU1 invocations and zero interpreter fallbacks or IOP
guest faults. CPU and GPU display captures were byte-identical; 2,705
window presentations succeeded. The tester confirmed audio restoration.

This is a bounded retail milestone, not a claim of complete game or
PS2 hardware compatibility. The input was not strictly neutral,
reverb was disabled on both cores, and full hardware differential
accuracy, other game modes, sustained play and other titles remain open.
The original 7,901-module full-image validation above is a distinct
static-discovery milestone, not the current expanded-cache inventory.

## Live translation-cache miss recovery

Auto-expansion now pauses the current native process at a missing guest function
instead of restarting the game after every newly compiled LLVM module. The
driver compiles and verifies the function, hot-loads a new native library, and
retries the same PC without repeating guest inputs, IOP work, or VBlank.

This is **in-process resume, not a disk savestate**. An interrupted process or
exhausted expansion budget still requires a new guest run. The default
`EXPANSION_PER_PASS=128` can be raised up to 1024 for longer live sessions;
`--replay-after-expand` on `tools/run_game.py` retains the legacy behavior.

See [Live cache-miss resume](docs/SDBZ_LIVE_CACHE_MISS_RESUME.md) for the
protocol, validation rules, acceptance target and limitations.

## BIOS-free extracted disc launcher (Windows)

Run `python tools/launch_ps2_gui.py` for the graphical launcher. Choose
the extracted disc folder and an optional raw PS2 memory card, then
select **Launch**. By default, the native raylib/WebGPU game opens
inside the launcher's new **Game window** tab, with build and runtime logs
still visible underneath. On the **Game** tab, uncheck **Show game in
launcher tab** to restore the standalone game window. The game viewport
resizes with the launcher. This Win32 embedding uses the live renderer and
input, not a screenshot; the game still runs as its own process.
The first available controller supplies PS2 port 1 input. The south face
button maps to Cross. Both sticks, the D-pad, Start, Select, and the
shoulder buttons are mapped. The launcher shows the build and game
log and saves it to `build/ps2-launcher.log`.

**Game** exposes all batch flags, including quick probe, matched replay
and cache recovery. **Performance** exposes PR #152's cold precompilation,
fast live-overlay DLLs and compile-job count. Indexed guest-PC dispatch is
always enabled for new native libraries. **Limits and diagnostics** controls
dispatch budgets, timeouts, custom Cross pulses and trace settings.
**Direct command**
shows separate tabbed forms for `run_boot_session.py`, `run_game.py`, and
`ee_game_runner.exe`. Each tool retains its own inputs. Hover over a
field for help or use **Show --help** for the selected tool’s CLI help.
New forms start with the full-replay defaults from `run_ps2_game.bat`.
Use **Apply batch defaults** to reload those values for the selected tool.
For repeatable IRX options and extra arguments, enter one item per line
and leave paths with spaces unquoted.

The launcher prefills the boot script’s defaults and restores choices
from `build/ps2-launcher-settings.json`. It saves on launch and when
you close the window. Clear a numeric field to use the script’s
automatic value.

The **Performance** tab defaults to **Precompile all functions on a cold
cache** and **Fast live overlays**. On a cold cache, the batch launcher
translates the whole statically discovered guest function set once; a valid
existing cache stays intact. A live cache miss links only new function objects
into a small DLL, then folds the overlays into the full cache on exit.
Uncheck **Fast live overlays** to use `--live-full-relink` for comparisons
(the Game tab must still have **Resume after cache miss** checked).
The Compile jobs field is blank by default, allowing the batch script to
select the host CPU count. Existing saved numeric overrides are retained.
For direct runs, the Boot session and Game runner forms independently expose
`--functions=all` and `--live-full-relink` along with their other controls.

The **Performance** tab includes optional guest provenance diagnostics:
**Watch guest word**, **Trace guest stores**, and **Trace V0 writes**.
To investigate the SDBZ sound-handle field, use `0x0044081c` for the
first two fields and `0x00137970:0x00137d18` for the V0 trace range.
The standard GUI and batch launcher forward these read-only probes to
both the expansion phase and final graphics replay. They are blank by
default and never repair an invalid guest pointer or suppress an EE
exception. The V0 probe prints up to 64 matching assignments. The
STORE probe prints the first 64 matches and retains the most recent 64
guest STORE instruction operands in a host-only ring, which is dumped
at the end of either a successful or faulting replay. A new retail run
is needed to confirm the handle's provenance.

The **Game** tab now includes **Resume after cache miss**, enabled by default.
When an uncached EE function is reached, compilation and native-library
replacement happen without restarting the current game process or repeating
the controller input; on the fast path this uses overlay libraries rather
than a full-library relink each time. Uncheck it to use the original restart-on-miss path.
The **Limits and diagnostics** tab accepts up to 1024 functions per expansion
pass (128 by default). The **Direct command** forms for both the boot session
and Python game runner expose `--replay-after-expand`. This is not a persistent
savestate and does not survive closing the process.

Place the original, extracted game disc files under `PS2_GAME/` at the
repository root, including `SYSTEM.CNF`. Run:

```bat
run_ps2_game.bat
```

The script reads the `BOOT2 = cdrom0:\\...;1` entry from
`PS2_GAME/SYSTEM.CNF` and resolves its ELF case-insensitively, with no
hardcoded region or executable filename. It configures/builds the native host
tools, then runs `tools/run_boot_session.py` with
`--disc-folder=PS2_GAME` and `--disc-root=PS2_GAME`.
It neither requires a raw ISO nor downloads/executes ROM0, and does not
change your Git branch. Logs and the JSON report go to
`build/ps2-game-hle/`. `PS2_GAME/` is gitignored.

With a verified translation cache, `run_ps2_game.bat` stops after the
bounded coverage probe and writes `quick-probe.json` and `quick-probe.log`.
Run `run_ps2_game.bat --full` for the full dispatch trace, IOP catalog, and
GS snapshots. Cold builds and explicit WebGPU requests also use the full path.
The cached quick probe defaults to 100,000 EE dispatches, whereas the full
retail diagnostic run defaults to 500,000. Use `run_ps2_game.bat --quick`
to **force a non-traced probe** even when the preserved guest translation
cache cannot be reused after pulling changes. The script still rebuilds
or relinks guest IR as required; it simply avoids the large final trace.
An explicit `--quick` takes priority over WebGPU snapshot/window
environment flags, disabling capture only for that launcher invocation.
Without `--quick`, WebGPU requests still select the full replay. Both remain bounded and stop
at real guest failures; a longer run does not imply that a pending RPC
has completed. Cached probes now include bounded outstanding-IOP-RPC
thread/PC checkpoints and final instruction/register samples without
the large per-dispatch full trace. For a long cached probe, use
`set MAX_DISPATCHES=4000000` and `run_ps2_game.bat --quick`; inspect the
**current** `quick-probe.log` and `quick-probe.json`, not preserved
`boot.log` or `first-boot.json`. Override the per-pass ceiling or
subprocess timeout for a full traced run with:

```bat
set MAX_DISPATCHES=1000000
set BOOT_TIMEOUT_SECONDS=180
run_ps2_game.bat --full
```

You may run `set PS2_GAME_RESOLVE_ONLY=1` first to verify the BOOT2
resolution without building or running the game. Optional
`EMIT_JOBS` and `SIF_POLL_LIMIT` environment variables adjust the
native session diagnostics.

## Reproducible retail profiling (Windows)

With an existing compatible EE cache and VU1 AOT library at
`build/vu1-native-v20`, run the bounded P40 preset. It performs
`git pull --ff-only`, uses separate 40-million-dispatch budgets and
enables native asynchronous workers, profiling and WebGPU capture.

```bat
set "SDBZ_P40_LISTEN="
set "SDBZ_HOST_AUDIO=0"
run_sdbz_p40.bat
```

For listening at the guest speed target with host audio:

```bat
set "SDBZ_P40_LISTEN=1"
set "SDBZ_HOST_AUDIO=1"
set "SDBZ_AUDIO_PROFILE=1"
set "SDBZ_PROFILE_PCS=1"
run_sdbz_p40.bat
```

Keep the EE and VU1 caches unless their translation provenance changes.
Do not compare uncapped and paced wall times as speedups. A nominally
neutral scripted preset does not exclude physical controller input.
Unknown services and guest failures remain explicit; the runner does
not synthesize hardware progress to force a successful boot.

## Original console test suite

Run `python tools/run_ps2autotests.py --list` to enumerate the pinned 55 original ELF tests. The default is four parallel tests; override with `--jobs 8 --emit-jobs 1` or use `--jobs 1` for sequential validation. The CI pilot is sharded; manually dispatch Build and test with `autotests_full` enabled to run all 55 in parallel groups. See [ps2autotests validation](docs/PS2AUTOTESTS.md) for execution and exact-output comparison. The recorded Windows full-suite baseline at `b698e1c` is 20/55 exact transcripts (11 DIFF, 24 INCOMPLETE); clean guest termination is tracked separately. Subsequent CI at `53392cf` confirms exact funnel and shuffle transcripts (22 distinct matches across runs; subsequent `b021e1b` confirms cpcond for 23 distinct matches; fresh full suite pending). VU0/VU1 launch and VU0 flag-readback work is under validation. Synthetic vectors are not counted as complete ELF passes.
