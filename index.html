01 / THE PIPELINE

From instructions to execution.

Static analysis meets native compilation. Each stage preserves a traceable path back to the guest program.

  1. 01 ↗
    0100

    Decode the ELF

    Read executable segments, discover functions and control flow, and decode R5900 instructions.

    MIPS / R5900
  2. 02 ↗
    { IR }

    Lift to LLVM IR

    Model register state, branches, delay slots and instruction semantics as verifiable IR modules.

    LLVM
  3. 03 ↗
    ▤↗

    Compile native code

    Verify and emit host objects, then link them behind a guest-PC dispatcher.

    NATIVE OBJECTS
  4. 04 ✓
    ▣●

    Run with devices

    Execute guest code alongside IOP, DMA, SIF, GIF/GS and native WebGPU integration.

    RUNTIME / WEBGPU

02 / UNDER THE HOOD

Built for the hard parts.

The goal is original guest behavior, not a reimplementation of the game's logic. Unsupported behavior is investigated rather than silently skipped.

⌘COMPILER

Instruction-accurate ambitions.

R5900 integer and multimedia operations, COP1, selected COP2/VU0 behavior, branching, delay slots, and cross-block register liveness are validated with focused tests.

decode→lift→verify→link
▧GRAPHICS

Real GS output.

Committed GIF traffic feeds a native WebGPU rendering path with actual GS framebuffer selection and field-driven presentation.

See the milestone ↗
⌁HARDWARE

More than CPU code.

HLE-first devices, guest IOP modules, SIF/RPC, DMA, controller transactions, memory cards, and experimental BIOS support.

◎OBSERVABILITY

Debug the machine, not just the symptom.

Translation provenance, deterministic replay logs, CPU/GPU readbacks, IR validation, hardware event counters, and targeted regressions help isolate faults without inventing guest progress.

03 / DEVELOPMENT STATUS

A real frame.

Super Dragon Ball Z (USA) has produced visible native WebGPU output from original guest instructions. A cross-block EE lifting bug was fixed to restore the framebuffer width written by the game itself.
